# DeepSeek 行业补全与通话评估

第三板块在本地服务内运行，包含持久化任务队列、DeepSeek JSON 请求、行业补全、带原话证据的通话评估、分页记录与录音回放。FreeSWITCH 和真实 SIP 外呼仍待接入。

## 配置与启动

在现有 `.env` 中增加下列变量，然后重启后端；不要覆盖已有 SeedDuplex 密钥：

```dotenv
DEEPSEEK_API_KEY=填写自己的密钥
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

`deepseek-flash` 是官方 API 的模型别名，当前官方定价页标注对应 **DeepSeek-V4.1-Flash-1017**；不要把展示名 `DeepSeek 4.1 Flash` 直接填为 API model。别名后续可能随服务升级，实际映射以[官方模型与价格文档](https://api-docs.deepseek.com/quick_start/pricing/)为准。项目使用 `/chat/completions`，关闭思考模式、非流式响应，并按[官方 JSON Output 说明](https://api-docs.deepseek.com/guides/json_mode)设置 `response_format: {"type":"json_object"}`，提示词包含输出结构与 json 示例。`DEEPSEEK_BASE_URL` 可改为兼容服务的根路径（支持含 `/v1` 的根路径）；程序会追加 `/chat/completions`。

密钥只在后端 Authorization 头使用，不传到浏览器，不写入提示词或导出结果。未配置密钥时任务保留 `pending`，不会生成假分析。界面“已配置”仅表示存在环境变量，不代表已验证鉴权、额度或实际模型效果。

## 行业补全

1. 导入客户 JSON，统一校验后按规范化电话保存。保留输入的其他客户字段，再新增或更新 `industry`；内部 `id` 由服务端管理。
2. 缺少行业的客户进入 `industry_jobs`。worker 每批领取最多 20 位，向模型仅发送客户内部 ID 与 `camp` 公司名，不发送客户电话、姓名、地址。
3. 模型按公司名中的明确线索给出简短行业，例如门窗、口腔医疗。仅有科技、实业、商贸等含混描述时填 `未知`，不编造经营范围。返回 ID 必须与输入逐一匹配，缺失、重复或额外 ID 均视为失败。
4. 已有明确 `industry` 优先保留；补全过程中若客户公司发生变化或被手工填入行业，旧任务不覆盖新资料。相同公司重复导入而未提供行业时保留已有行业。
5. 新建语音会话将行业同时作为 `industry` 与 `&industry` 注入客户数据块；行业不明确时，语音话术使用中性场景或向客户确认。行业补全完成前已开始的会话保持原始快照，不在通话中途改资料。

行业队列状态可在客户页查看。`GET /api/customers/export` 导出补全后的资料，移除内部任务状态字段；不会改写您原来的 CRM 导出文件。

## 哪些通话会评估

只有已接通并已结束的 SeedDuplex 语音试打参与评估，包括接通后异常结束；文字规则模拟与未接通失败排除。当前 `answeredAt` 表示本地语音试打收到 SeedDuplex `session.created`、语音会话初始化成功，**并不表示已通过 SIP 拨通真实客户**。未来电话网关必须改用真实 `call.answered` 事件写入接通时间。

后台读取最终态 `AsrText` / `ChatText`，不将临时转写重复送入模型。连续客户 ASR 片段合并为一轮；客户回应之间需要销售发言才算新一轮。只含喂、你好、嗯啊等空泛声音不计有效轮次，明确拒绝、询问或许可计入。AI 第一轮包含固定开场白，不按一句话中的逗号或句号拆成多轮。

系统将泓动引擎的 GEO 企业销售背景、筛选意向而非成交的目标、等级规则和当前通话资料送给模型。公司名称和对话中出现的指令作为数据处理，不得改变分析任务。

## 意向等级

| 等级 | 展示 | 标准 |
| --- | --- | --- |
| A | 有明确意向 | 客户许可加微信/微信接收案例，并确认拨打号码就是微信绑定手机号，或给出另一已确认的微信手机号/微信号 |
| B | 可能有意向 | 至少两轮有效客户回应；即使说过不需要、不感兴趣或未许可加微信，也满足 B 的轮次要求 |
| C | 无意向 | 正常结束时，客户在 AI 第二轮发言前挂断；或客户明确拒绝且不足两轮有效回应 |
| D | 用户在忙 | 客户明确因开会、开车等无法当前沟通，或要求稍后再联系 |
| E | 其他 | 证据不足、号码错误、其他情况；没有客户意向证据的传输异常归此类 |
| F | 智能助理 | 语音信箱、自动接听或电话助理，非真人客户接听 |
| G | 骂人 | 对销售有明确辱骂、人身攻击；普通拒绝不属于此类 |

判定优先级为 **A → F → G → D → B → C → E**，颜色分别展示。B 的轮次要求不以时长替代；愿意听、询问价格和销售方说“我加您”均不自动得到 A。

模型结果还经过服务端校验：证据 ID 必须来自客户最终转写，引用片段必须逐字存在；不能把 AI 文本作为客户证据。微信许可、同号确认和异号/微信号必须能在被引用的客户发言及其上一条销售提问中核实，未说过的手机号不能由模型补造。手机号只接受 11 位大陆手机号；无已确认联系方式的 A 会降为符合规则的等级。最终轮次、模型名与评估时间由服务端写入。

每条结果保留 `grade`、`summary`、`reason`、客户原话 `evidence`、`wechat` 联系事实、有效轮次、模型与评估时间。A 级列表中，微信同号显示“与电话同号”，异号显示确认的 11 位电话；单独提供微信号时可在详情查看。A 表示取得联系许可与联系方式，不代表已经发送好友申请、添加成功或成交，仍需人工复核。

## 队列与重试

行业与通话队列保存在 SQLite 中。通话分析状态为 `not_requested`、`pending`、`running`、`completed`、`failed`；行业任务使用后四种状态。每通结束通话只对应一个分析任务。服务重启时，运行中的任务恢复为待处理；已完成结果保留。

每次请求默认 45 秒超时。所有请求和校验失败都会记录错误。网络异常、超时、429、服务端故障、空内容和截断等可重试错误，最多自动尝试 3 次；前两次失败后约等待 1 秒、5 秒再尝试。鉴权、输入和结果结构/证据校验错误直接标为失败，避免重复扣费。失败不会写成已完成，也不阻止查看原通话。之后可从详情页手动重新评估；行业失败可从客户页重试。重新评估结果仍需结合原文确认。

## 记录页面与录音

通话列表由服务端分页，支持自定义每页条数（1–100）、按开始/接通/结束时间选择日期范围、快捷日期、仅显示接通、客户/公司/电话搜索、等级筛选，以及开始时间、状态和意向度排序。日期按浏览器本地日期生成边界，API 接收带时区 ISO 时间；`from` 包含、`to` 不包含。

详情按角色展示客户与 AI 的对话、时间和分析证据，并可播放真实浏览器录音。录音混合已允许上传的客户麦克风与 AI **实际播放**的音频，保留打断后的实际播放结果；首句锁期间和手动静音期间的麦克风保持静音。录音格式由浏览器支持决定，为 WebM、MP4 或 Ogg，不会用转写合成“原录音”。云端完整生成文本可能包含被客户打断、尚未播放的内容，因此文本与录音不必逐字相等。

结束后请保持页面打开，等待录音保存完成。活动语音、录音上传或未保存录音存在时，刷新/关闭页面会触发浏览器离开提醒。上传失败的音频保留在当前页面，可重试保存或下载备份；强制关闭仍可能丢失未上传的音频。浏览器不支持录音、上传失败或历史版本没有录音时，详情明确显示无可用录音。默认文件保存在 `data/recordings/`，也可配置 `GEO_RECORDINGS_PATH`；单文件上限 25 MiB。SQLite 存录音元数据和 URL，备份时应同时保留数据库与录音目录。未来 SIP 通话应使用电话网关提供的独立线路原录音。

## HTTP 接口

| 接口 | 用途 |
| --- | --- |
| `POST /api/customers/import` | 导入客户并自动入队补全行业；body 为 `{ "customers": [...] }` |
| `POST /api/customers/enrich` | 重试缺失行业任务；body 可含 `{ "retryFailed": true }` |
| `GET /api/customers/export` | 下载带行业的客户 JSON |
| `GET /api/analysis/status` | 模型配置状态与通话/行业任务数量，不包含密钥 |
| `GET /api/sessions` | 分页查询，返回 `{ items, total, page, pageSize }`；列表不携带整通转写 |
| `GET /api/sessions/:id` | 完整详情、转写、分析状态/结果与录音元数据 |
| `POST /api/sessions/:id/analyze` | 将已接通且已结束的语音通话重新入队；其他会话返回 409 |
| `GET /api/sessions/:id/export` | 导出原会话、事件与分析结果 |
| `POST /api/sessions/:id/recording` | 上传真实音频二进制，Content-Type 为 audio/webm、audio/mp4 或 audio/ogg |
| `GET /api/sessions/:id/recording` | 浏览器音频播放与范围读取；无录音时返回 404 |

列表查询参数：`page`、`pageSize`、`answeredOnly=true|false`（默认 true）、`dateField=createdAt|answeredAt|endedAt`、`from`、`to`、`sortBy=createdAt|status|grade`、`sortDir=asc|desc`、`grade=A…G`、`search`。不会用只拉取前 100 通的方式计算全量分页。

## 验证范围

运行 `npm run typecheck`、`npm test`、`npm run build`。`tests/deepseek.test.ts` 使用本地 HTTP mock 验证 JSON 请求、行业 ID 精确匹配、空内容/截断/无效 JSON、取消请求、客户证据校验、微信事实、轮次和等级边界。其他集成测试覆盖队列持久化与重试、分页筛选和录音存储。

这些检查不调用真实 DeepSeek，不验证账户余额、服务权限、真实行业识别准确率或真实通话评分质量。补入密钥后应使用有人工标注的样本核对等级与号码，语音录音还需要在实际浏览器中完成一通试听验收。
