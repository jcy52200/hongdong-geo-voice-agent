# 本地同行查询与竞对场景

更新：2026-11-07。此功能扩展客户导入、现有 DeepSeek 后台任务和 SeedDuplex 提示词，不增加外呼调度或实时通话中的自动工具执行。

## 使用方法

1. 在“客户资料”手动添加客户，或导入原有 JSON 数组 / `customers` 对象。继续使用 `camp`、`name`、`phone`、`address`、可选 `industry`；地址建议明确写到城市，如“河北省石家庄市”。
2. 后台先补全缺失行业，再查询同城同行。客户表新增“本地同行 / 来源”，可查看查询状态、最多两家企业、来源链接和查询时间。
3. 资料齐备后，新建通话会把名称带入 `&competitors`。已经创建的通话保留原快照，不会中途更换竞对。若查询还未完成，可以继续测试语音，此时只泛称当地同行。
4. “智能体配置 → 模型参数 → 本地同行场景”可开关场景，优先级固定为中上。完整限制词页的客户变量说明和草稿预览包含 `&competitors`。
5. 旧客户可点击“查询本地同行”；完成、失败或跳过后可重新查询。重复点击正在等待/执行的任务不产生第二个任务。同样资料重复导入会复用已有查询结果，修改公司、城市或行业后重新查询。

配置继续使用 `DEEPSEEK_API_KEY`，不需要其他搜索供应商的密钥。当前实现调用 [DeepSeek 官方 Search API](https://api-docs.deepseek.com/guides/search/) 的 `POST /v1/tools/search`，然后由现有 `deepseek-flash` 从结果中筛选同行。搜索和模型处理属于独立请求，并非只在提示词里写“请联网查询”；账户需具有相应接口权限和可用额度。

默认从 `DEEPSEEK_BASE_URL` 推导搜索地址，去掉末尾 `/v1` 或 `/beta` 再追加 `/v1/tools/search`。如使用只代理聊天接口的兼容服务，可单独设置 `DEEPSEEK_SEARCH_BASE_URL`；它仍使用同一个 DeepSeek Key，须保证该地址受信任并接受此凭证。不要把网站地址当作 API 根地址。修改环境变量后重启后端。

## 搜索与证据

- 行业仍根据公司名补全；查询需有明确城市和行业，不拿省份冒充当地。缺少城市或行业未知时标为 `skipped`，说明需补充什么，不凭记忆编两家公司。
- 搜索请求只包含城市、行业和“公司 / 厂家”关键词，不发送客户联系人、电话、完整街道地址或通话记录。筛选模型收到公司名、城市、行业和最多八条搜索资料。
- Flash 最多返回两家同行，并指定来源编号与公司名、城市、行业三个逐字片段。服务端逐项确认名称、城市和行业出现在引用中，且引用确实存在于同一条检索资料；排除无效来源、重复名称及客户自身。关联关系和经营范围仍属于基于网页的模型筛选，不能等同工商审计或已确认的竞争关系，支持人工点击来源复核。
- 没有合格结果就保留空名单。网页中夹带的命令只是数据，不会执行；返回的来源 URL 只作为资料链接，不由本地服务自动抓取任意地址。
- 这些名称只表明找到同城同行候选，**不能证明对方已经购买 GEO、被豆包推荐或与泓动引擎合作**。

客户 JSON 增加 `competitors` 数组及 `competitorArea`、`competitorCheckedAt`、`competitorNote`，保留原始 CRM 附加字段。每个候选包含 `name`、`area`、`industry`、`sourceUrl`、`sourceTitle`、`nameEvidence`、`areaEvidence`、`industryEvidence`。客户页面另有内部任务状态和错误；导出 JSON 时移除状态/错误，保留结果与来源。

导入文件里的候选名单、状态和查询时间不会被直接当成已核验结果；已有客户只复用服务端保存、且公司/地址/行业全部相同的结果。这样可避免导入的伪造来源或旧城市名单直接进入真实语音。

## 话术与优先级

`&competitors` 的口语值是用“、”连接的最多两个名称；`CUSTOMER_JSON.competitors` 同时保留名称数组，不把网页长文塞入语音限制词。只有来源、当前城市和行业一致的名称才能进入名单。

中上优先级指：客户明确问题、停止要求和已经表达的微信联系方式优先；在解释行业场景、讨论为什么做 / 什么时候做、客户犹豫或主动谈同行时，竞对例子优于泛泛地重新介绍产品或机械追问微信。主动场景整通最多一次。

示例（甲、乙仅为说明，实际名称来自本通快照）：

> 嗯，比如在咱们石家庄，要是甲公司、乙公司这些同行先把 GEO 做起来了，咱们还没做，那客户问豆包哪家门窗合适的时候，答案里就有可能先提到他们，咱们被看到的机会就少一些。要不我把咱们行业的案例发您看看？

必须保留“要是 / 如果”和“可能”，不能说成“他们已经做了、客户已经被抢走”。有一家只说一家；空名单只泛称当地同行。已经获得微信许可则推进同号 / 异号确认，确认后及时收尾，不再施压。客户追问竞对是否真的做了时，明确说明这是举例，尚未确认。

问答优先级和竞对规则保存在 `prompts/response-policy.md`，每次 `buildPrompt()` 都附加，包括保存过的自定义正文。默认正文升级到 `2026-11-07-local-competitors`；只迁移精确匹配的旧出厂模板并备份，自定义正文、音色、开场和历史快照保持。开关由 `AgentConfig.competitorPressureEnabled` 控制，默认开启。

## 之前错答的修复

用户提供的错答序列可在旧文字预演中复现：`怎么做的` 没匹配实现方法，`能保证这个100%吗` 没匹配曝光保证，后续未命中的问题又回落成首轮长介绍。

现在文字预演和逐通规则分别覆盖：

- “怎么做的”直接回答媒体内容、自媒体和官网部署的方法，不反问是否了解。
- “具体做什么”解释业务；“再解释一下”换个行业例子，不原封重放长介绍。
- “能保证这个100%吗”先说不能保证百分之百，再解释既有口径的范围。
- 首轮拒绝长介绍只用于第一次简单拒绝，具体问题不触发。竞对场景不能抢答上述问题；连续追问不每句重复邀请微信。

文字预演是确定性流程检查，不能证明真实 SeedDuplex 的每次措辞都相同；真实语音仍需听测。固定首句由 AI 先说且不可打断的媒体保护保持。

## 队列与接口

- `competitor_jobs` 持久化单客户任务、输入快照、revision、次数和错误。缺行业时等待行业任务；每轮最多查询一家，通话后分析保持优先。
- `pending / running / completed / failed / skipped` 分别表示等待、执行、完成、失败、资料不足跳过。无 Key 留 pending；空搜索是完成但没有候选，不伪装为 API 失败。
- 网络/超时、408、429、5xx 最多尝试三次；认证、余额、接口不可用或结构错误不盲目重试。关闭会中止请求并恢复任务，重启可继续。输入和 revision 同时匹配才回写，迟到结果不会覆盖重导入或重查后的客户。
- `POST /api/customers/import` 自动安排行业与同行任务。
- `POST /api/customers/:id/competitors/research` 查询/重新查询一家客户；未知 ID 返回 404，已有待执行/执行中任务复用。
- `POST /api/customers/enrich` 同时处理缺失行业与未查/失败/资料不足的同行任务。
- `GET /api/analysis/status` 和 bootstrap 增加 `competitorPending / competitorRunning / competitorFailed`。
