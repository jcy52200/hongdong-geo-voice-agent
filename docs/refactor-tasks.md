## 第一次：拆开语音核心与浏览器

目标是让浏览器成为一种媒体适配器，使未来电话网关可以复用同一套 SeedDuplex 会话逻辑。保留现有模型参数、固定首句、FAQ 快回复、行业变量、提示词快照、通话记录、录音回放与 DeepSeek 评估。

### 工作包

| 工作包 | 拆掉或修改 | 复用 / 形成的边界 |
| --- | --- | --- |
| 语音核心 | 将媒体 WebSocket、事件订阅与 Seed 生命周期从同一对象中分开；由统一核心处理结束、失败与资源清理 | 现有 Seed 协议、增量转写归并、快回复、首句门控、配置干预与逐通上下文 |
| MediaPort | 明确音频格式、媒体就绪、输入/输出、清空、响应结束、播放排空和断线事件；核心不直接依赖 `ws` | 浏览器适配器继续承接 `/ws/sessions/:id`，保留旧客户端协议 |
| 首句门控 | 仅在模型该响应生成完成且对应媒体响应真实排空后解锁；拒绝旧响应或无关响应解锁 | AI 先说固定首句，首句不可打断；后续插话清队列逻辑保持 |
| 生命周期 | 分开“媒体所有者断开”和“只读观察者断开”；核心的 finish/fail/cleanup 幂等 | 浏览器试听的媒体断线仍可结束本次测试；单个会话不接受第二个媒体所有者 |
| 只读观察 | 添加独立状态与转写订阅；禁止观察通道发送音频、播放确认或模型控制 | 观察不承担播放责任，断开不结束语音会话；沿用本地 API 的访问边界 |
| 共享类型 | 统一来源、模型就绪时间和必要会话状态；服务器与网页不再分别手写同一领域形状 | 浏览器与历史来源可辨识，为电话来源预留类型边界，不实现电话网关 |
| 数据迁移护栏 | 用可追踪、可重复安全运行的迁移替代每次启动无范围回填；历史 `answered_at` 与模型 ready 语义分开 | 不删除客户、设置、配置/提示词快照、转写、评估或录音；旧试听数据可查看，未知来源不伪造客户接通 |
| 回归与文档 | 验证上面新的边界，并更新实际结构和接入说明 | 复用既有提示词、协议、队列、分析、录音与界面回归基线 |

既有通话后 DeepSeek 分析队列继续运行；它不是新开发的外呼任务队列。现有人工 `session.update`、人工回复干预和工具结果协议继续保留；自动工具执行属于第三次。

### 第一次验收

- 现有文字预演与浏览器 Seed 试听入口可用，模型参数、音色与客户变量仍进入逐通快照；不恢复已删除的软电话入口。
- 使用不依赖 WebSocket 的媒体替身可驱动同一会话核心；浏览器适配器只负责协议转换和媒体生命周期。
- 首句需同时满足模型 done 与媒体 drain；旧响应回执、重复回执和无关回执不能提前解锁。后续清空逻辑与两通隔离保持。
- 独立观察可接收状态/转写；观察断开不结束通话，观察消息不能冒充媒体输入或播放完成。媒体断线与明确结束仍正常收尾，重复结束不重复清理或入队。
- 新库和旧库迁移均可重复启动；历史接通时间、来源和提示词/配置保留，未来电话来源不能被模型初始化事件回填为接通。
- 运行 `npm run typecheck`、必要回归与 `npm run build`；记录真实结果及仍需云端试听的限制。

### 第一次明确不做

不安装 Siphon/FreeSWITCH、不配置阿里号码、不部署 ECS、不发出真实电话；不新增外呼任务队列、槽位预约、批次调度、预测拨号、时段/频控/停止名单准入或自动工具执行。无需为这些待实现能力建立一套空业务框架。

### 第一次实际交付记录

已完成本地实现，实际边界如下：

| 文件 / 接口 | 实际交付 |
| --- | --- |
| `server/voice/session.ts` | `VoiceSessionManager` 接受通用 `MediaPort`，管理 Seed、首句、转写、快回复、人工控制和收尾；不再直接解析浏览器 JSON 或依赖 WebSocket/Zod |
| `server/media/port.ts` | PCM 输入/输出、带 `playbackId` 的播放段、生成结束/媒体排空、清空与断线契约；缺少排空能力的媒体不能启动 Seed 试听 |
| `server/media/browser.ts`、`server/sessions.ts` | 浏览器 JSON/Base64 校验和转换移至适配器；旧 `SessionManager.attach()` 作为兼容入口，已有 `/ws/sessions/:id` 继续可用 |
| `/ws/sessions/:id/observe` | 独立只读观察 WebSocket，先发会话快照，再推状态、转写等元信息，不推可播放音频；保留 Host/Origin 本地防护；任何入站消息以 1008 关闭该观察端，不影响媒体端 |
| `shared/session.ts` | 客户、配置、会话、转写、录音、来源与事件类型由服务端和网页共同使用；`softphone_bridge` 只保留历史来源，不恢复入口 |
| `server/store.ts` | 增加 `schema_migrations`、`modelReadyAt`、`answerSource`；旧 Seed 浏览器/已退役软电话记录只做一次有范围迁移，保留原时间、资料、快照与评估；未知或未来来源不根据 `session.created` 伪造接通 |
| 浏览器播放与核心门控 | 新前端回传 `audio_done.playbackId`；核心先确认非空有效 PCM 与对应响应生成结束，再接受该播放段排空；错误/过早/旧段回执不解锁，已取消响应的迟到音频不重播 |
| `server/seed.ts`、应用关闭 | Seed 关闭可等待且有超时上界；会话清理幂等，应用关闭等待资源收束并拒绝关闭期间的新连接 |
| `server/contracts.ts` | 接入契约更新为 2.3，报告语音核心已实现情况；真实电话拨号仍为预留能力，第三次控制平面仍待开发 |

保留兼容：旧浏览器客户端缺少 `playbackId` 时，只有 `BrowserMediaAdapter` 在已收到生成结束后才将其映射到本地完成段；它不能提供新客户端同等的端到端段标识保证。未来电话媒体适配器必须返回明确的播放段完成证据，不能沿用无 token 的兼容捷径。

最终验证：`npm test` **80/80 通过**（原基线 62，新增迁移 3、语音核心 11、观察链路 4）；`npm run typecheck` 与 `npm run build` 均通过。新增回归覆盖不依赖 WebSocket 的媒体替身、首句双条件、跨通隔离、旧响应和回执、输出失败、观察断开/异常入站、迁移反复启动与未知来源保护，以及有界关闭与关闭期间的新连接防护。

仍未验证真实 Seed 云端音频、阿里号码、SIP/网关媒体、手机实听、线路原录音和并发容量。这次没有安装网关、部署 ECS 或发出真实电话，没有提前实现第三次控制平面。

目标是证明一通电话能复用第一次的核心。用户选择阿里平台提供的号码，不假设已拥有可任意使用的 SIP trunk；先确认获准的 CCC 终端/API 路径，再确定 Siphon 或 FreeSWITCH 的首个实现。

| 单通现场验证 | 平台号码拨获准测试手机，测试开场、打断、FAQ、微信同号/异号、早挂、故障及观察页断开 | 记录真实延迟、音质、状态和录音证据；自动测试不代替真人实听 |

### 第二次验收

- 同一获准平台号码可完成单通拨入测试手机；真实客户腿接通、振铃、忙线、未接和取消能准确映射。
- 电话链路不依赖浏览器保持打开；观察退出不挂机，电话信令挂断可释放媒体与 Seed 资源。
- 手机上首句完整且不能被模型/本地 VAD 抢断；后续打断可清除未播放音频，旧排空回执不会解锁错误响应。
- 双向声音、真实时间、逐句转写、线路录音和 A–G 评估证据一致；未接通不参与意向评估。
- 格式错误、媒体过载、Seed/网关断线、重复/迟到信令均有明确结果，无跨通话音频或资源残留。
- 类型检查、必要自动回归和构建通过，现场未完成项明确列为未验证。

## 第三次：控制平面

目标是在已验收的电话通道上，决定打给谁、何时打、打完做什么，并把所有自动业务行为留在这一层。此时才对业务用户提供受控单通与批次外呼入口。

### 工作包

| 工作包 | 交付 | 关键约束 |
| --- | --- | --- |
| 调度与槽位池 | 持久化外呼任务、可用容量、原子预约、拨号中占用、结束释放、CPS 与暂停/恢复 | 以线路/模型/媒体/应用容量最小值为上限；初期 1:1 预约，不做预测式超额拨号或 PID |
| 业务编排 | 客户选择、快照冻结、幂等外呼 API、单通/批次状态、有限重试、重启与未知结果核对 | 重复请求不发第二通；客户接通不等待空闲 AI；资源不明时隔离核对 |
| 自动工具执行 | 允许工具清单、参数校验、按 `call_id` 去重、超时与批次汇聚，正确回传官方 tool item | 不在实时音频路径执行慢任务，不混入通话后分析队列；CRM 写回、转人工等仅在明确需求和权限内实现 |
| 合规准入 | 可配置外呼时段、同号日/周频控、停止/退订名单及获准测试/业务范围校验 | 在发信令前完成校验；失败任务可追踪且不呼出，不把失败准入伪装成线路故障 |
| 业务界面与审计 | 任务创建、单通/批次操作、暂停/恢复、跳过原因、准入结果、工具记录、资源状态和统计 | 观察仍只读；显式结束才控制信令；模型/媒体/真实客户腿时间保持分离 |
| 容量与恢复 | 故障与重启恢复验证、分析/录音最终一致、必要监控 | 先单进程实测；只有确有瓶颈才引入多实例租约或数据库/队列替代，不预先增加 Kafka/Kubernetes |

### 第三次验收

- 同一幂等键、重复点击、超时重试、重启恢复均不重复外呼；未知活动呼叫能核对，预约只释放一次。
- 所有不符合时段、频次或停止名单的客户均在信令发出前被拒绝，并保留可解释结果。
- 实际拨号中加接通数不超过可用预约容量，CPS 有界；小规模获准测试无超额接通、无跨客户串音。
- 工具参数、允许范围、重复调用、超时和结果回传经过验证；业务工具失败不阻塞实时音频线程。
- 任务暂停/恢复、客户挂断、操作员结束、模型/媒体/网关故障和进程重启均能收束，记录、录音和分析可核对。
- 类型检查、自动回归、构建及小规模真实验收通过后，才声明控制平面可用于对应获准范围。
