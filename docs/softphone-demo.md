# 软电话桥接：单通真实电话演示

本模式让 Linphone 负责阿里云 CCC 的真实电话，本项目负责 SeedDuplex 对话。两者通过 Mac 上两个独立虚拟音频设备连接，适合测试音质、话术和自然度。项目继续在本机运行，不需要 ECS，也不需要 FreeSWITCH。

这是一种可拆卸的演示接入：切回“浏览器试听”即可恢复原来的麦克风测试。正式方案仍为 FreeSWITCH + SIP；此次没有实现拨号任务、SIP 注册、电话接通/挂机事件同步或批量外呼。客户变量、限制词、模型参数、逐句转写和分析继续复用现有模块。

桥接功能已完成软件验证，尚未完成真实 SIP 电话端到端联调；实际线路音质、延迟及远端播放效果仍需按下述步骤验收。

## 准备

- 阿里云 CCC 实例，以及通过平台申请、已绑定且允许外呼的号码。本次不使用企业自有号码；号码申请、用途审核、外呼权限与费用以实际线路服务商和阿里云账户为准。
- 一个可使用 SIP 话机的 CCC 坐席：初始化后取得 **SIP 话机分机号**、设备密码，以及实例对应的服务器、端口和传输设置。它不同于 Web 软电话分机号。
- Mac 版 Linphone、两个独立虚拟音频设备，以及支持页面指定音频输出的浏览器。页面会检查所需能力；不支持时换用支持的 Chrome/Edge，避免让声音落到默认扬声器。
- 已配置本项目的 `SEED_API_KEY`；需要行业补全、通话分析时另配 `DEEPSEEK_API_KEY`。SIP 密码只填 Linphone，不填客户资料或提示词，也不提交 Git。
- 一部由自己或知情测试者接听的测试手机。

阿里云官方以 Linphone 作为兼容性示例，说明了坐席 SIP 话机初始化、TLS、注册及录音设置。文档截图基于旧版 Windows 客户端，Mac 菜单名称可能不同，按当前客户端和实例信息填写；保留服务器证书校验，证书问题按官方指定证书方案处理。[阿里云 Linphone 接入说明](https://help.aliyun.com/zh/ccs/cccai/use-cases/connect-an-sip-softphone)

坐席需选择相应 SIP 设备/工作模式并配置可用外呼号码；是否由 Linphone 直接拨号，或由 CCC 工作台发起后在 Linphone 通话，应先在账户中验证。阿里云的办公电话模式支持 SIP 话机在线后的外呼，但可用模式以实例配置为准。[阿里云 SIP 话机与办公模式](https://help.aliyun.com/zh/ccs/cccai/user-guide/sip-device-and-work-mode)

此次开发不会安装驱动、购买号码、更改系统默认音频或实际拨打电话。上述准备完成后再做人工联调。

## 双向音频接线

准备两条独立通道，下面统一称为 **A：客户 → AI**、**B：AI → 客户**。

| 位置 | 输入 / 麦克风 | 输出 / 扬声器 |
| --- | --- | --- |
| Linphone | B | A |
| 本项目软电话桥接页面 | A（客户声音输入） | B（AI 声音输出） |

```text
测试手机 ⇄ 阿里云电话线路 ⇄ Linphone
                               │ 接收客户声音 → A → 页面输入 → SeedDuplex
                               └ 发送 AI 声音 ← B ← 页面输出 ← SeedDuplex
```

两边不要选择同一个虚拟设备，也不要把物理麦克风、整机系统声音或扬声器加入这两条通道。这样声音通过软件传递，无需外放；相同设备的名称不能代替真实隔离。若需要本地监听，单独接耳机监听，先确认监听没有回流到 A/B。

### 方案 A：BlackHole 2ch + 16ch

可从 [BlackHole 官方项目](https://github.com/ExistentialAudio/BlackHole#installation-instructions) 分别获取 2ch 和 16ch 版本，按其安装要求操作。两种版本作为不同设备使用：**A = BlackHole 2ch，B = BlackHole 16ch**。在“音频 MIDI 设置”及应用设备列表中确认两者都独立出现，再按上表接线；16ch 方向使用首个声道对，不做额外通道混音。应用或当前驱动版本无法正确识别时，先停止测试并改用下方两个双声道 Pass-Thru 设备，不能把单个设备同时用于两个方向。

BlackHole 的官方用法是发送应用选择该设备输出、接收应用选择同一设备输入。本接线在两个独立设备上分别应用这条规则；独立通道设计属于本项目的组合方案，并非阿里云认证方案。[BlackHole 应用间路由说明](https://github.com/ExistentialAudio/BlackHole#route-audio-between-applications)

### 方案 B：Loopback 两个 Pass-Thru 设备

如果已有 Loopback，可以创建两个双声道虚拟设备，命名为 `GEO Customer In`（A）和 `GEO Agent Out`（B）。各设备只保留默认 **Pass-Thru** 源与其一对输出声道，不添加浏览器、Linphone、系统音频或物理麦克风作为额外来源，不配置扬声器 Monitor，然后按接线表选择设备。

Loopback 的 Pass-Thru 设备同时出现在应用的输入与输出列表，发送方选择其输出、接收方选择其输入。两个独立设备用于分离两个方向；Loopback 是另行提供的软件，购买或试用条件以其官网为准。[Loopback 官方手册：Pass-Thru](https://rogueamoeba.com/support/manuals/loopback/?print=true)

## 一通电话的操作顺序

1. 启动项目，打开“模拟电话”，在“测试方式”的三项选择中选“软电话桥接（演示）”（另两项为“文字预演”“浏览器试听”），再选择本次测试客户。桥接使用 SeedDuplex，沿用该客户的完整提示词和模型配置。
2. 点击“授权并刷新设备”，授予浏览器音频权限，在“客户声音输入 · A”选择 A、“AI 声音输出 · B”选择 B。设备安装、重命名后列表未更新时，重新刷新或重开浏览器。点击“检查音频路由”可在启动前观察本地输入电平；点击“停止观察”结束检查。预检不连接 SeedDuplex、不上行、不录音、不播放测试音。它只能验证浏览器和设备，不代表 SIP 已注册或电话已接通；输出是否到达手机仍需实际联调。
3. 在 Linphone 中选择 B 为麦克风、A 为扬声器，并确认注册在线。检查两边的四处选择都与接线表一致；这时不启动 AI。
4. **先在 Linphone/CCC 人工拨号，确认手机已接通。** 首次联调先请测试者说话，观察 A 的输入电平；检查通过后勾选“我已在 Linphone 接通测试手机并核对 A/B”，点击“接通后启动 AI”。启动 AI 后再确认手机能听到 B 中的 AI 声音。振铃期间不要启动 AI，否则固定开场可能在对方接听前播放完。人工确认只是一条演示操作记录，系统没有读取真实 SIP 接通事件。
5. AI 按既有固定首句先讲话。首句期间页面上行保持锁定，播放端报告开场排空后才开放客户声音；之后按正常打断、FAQ 和微信确认流程对话。
6. 结束时点击页面的“结束 AI 会话”，等待录音保存，**另在 Linphone 挂机**。页面会常驻提示需要在 Linphone 挂机；停止 AI 不会挂断真实电话。手机先挂机也不会自动停止 AI，应及时结束页面会话。
7. 在通话记录检查转写、评估和录音。再次测试需创建新会话；想恢复原试听，只需切回“浏览器试听”并选择麦克风/耳机。

## 能验证的效果与边界

- 可以听到真实手机线路中的 AI 音色、自然度、客户打断表现，并查看同一套话术的转写、分析与微信信息提取。
- “首句不可打断”仍由本项目的模型输入锁和页面播放完成反馈实现；页面播放完成只能确认本地声音已交给虚拟输出，**不能证明 Linphone、运营商和远端手机的缓冲已经排空**。首句末尾的打断窗口及往返延迟要以实测为准，正式 FreeSWITCH 方案需接入电话侧播放反馈。
- 当前录音是页面选定的客户输入与页面实际播放 AI 音频的混音，不是运营商原始录音，也不保证覆盖开场锁、静音期间或 AI 启动前的声音。可以另用 Linphone 的录音功能作人工对照；不会自动导入或替换系统录音。
- 会话以 `softphone_bridge` 标记来源，旧记录默认属于浏览器试听。页面显示的开始、结束来自 AI 会话；人工确认是启动前提，接通时间仍沿用 AI 初始化口径，不是阿里云话单。不能据此计算真实接通率、计费时长或无人接听状态，评估等级仅用于演示。
- 只运行单通受控测试。软电话掉线、对方挂机、换设备等情况均需人工处理，不具备无人值守保障。

## 保持可插拔

桥接设置属于当前浏览器的音频接入，不进入销售提示词、SeedDuplex 参数或 SIP 配置；更换接入不改变客户变量、逐通快照及分析逻辑。页面只记住本机的设备选择，不持久保存检查通过状态或人工接通确认，每次仍需重新检查并确认。浏览器负责设备权限、采集、播放和本地录音，Linphone 负责电话。停用桥接无需卸载或迁移业务数据。

后续 FreeSWITCH + SIP 通过独立电话媒体适配器接入现有语音会话，再补电话侧接通/挂机、播放清空/排空和原始录音来源。正式电话适配器直接处理媒体，不依赖 Linphone、虚拟声卡、浏览器或本机扬声器；本演示模式不会被当作正式拨号实现。
